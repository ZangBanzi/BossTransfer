# 技术验证计划

## 目标

阶段 0 只验证边界和可行性，不编写未经核实的生产接口。所有真实外部调用必须可复现、可回滚、不修改线上服务。

## 探针

| 探针 | 输入 | 成功标准 |
|---|---|---|
| Emby | `BaseUrl`、管理员 API Key | 返回版本和服务器名，不暴露 Key |
| NextEmby | `BaseUrl` | 至少一个健康或首页端点可访问，记录版本信息或未知 |
| NextFind | `BaseUrl` | 8092 服务可访问，记录版本信息或未知 |
| 115 | 无凭证时只访问开放平台；有开发者凭证后另建探针 | 无凭证不触碰账号；有凭证时只调用官方文档允许的只读/创建测试能力 |
| CloudDrive2 | `BaseUrl`、后续 API Token | 19798 可访问；生成 gRPC 客户端后验证系统信息、权限和任务查询 |

## 阶段 1 前置门槛

- 安装 Go 当前稳定版。
- 安装 Python 或选定替代测试工具。
- 安装 npm 或 pnpm，用于 Vue 前端。
- 安装 Docker 与 Compose，用于管理端容器验证。
- 获取 fnpack 和至少一台 x86 fnOS 测试设备；ARM 设备可在打包前准备，但发布前必须真实验证。

## 外部闭环测试

首个真实闭环只使用管理员授权的测试小文件，且必须满足：

- 测试文件非敏感、体积小、可删除。
- 使用测试 Emby 库、测试 NextEmby 用户、测试 115 账号和测试 CD2 目录。
- 分享、接收、复制、状态回报全链路使用同一 `task_id` 和 `trace_id`。
- 测试结束不删除用户已有数据，只清理测试目录中明确创建的测试文件。

## 失败注入

每个适配器至少覆盖：

- 401、403、404、409、429、500、502、503。
- DNS 失败、连接超时、读超时、连接重置、TLS 失败。
- 空数据、畸形响应、重复事件、乱序事件。
- 进程重启、数据库锁定、磁盘写满、端口冲突。

## 输出证据

- 探针命令、时间、脱敏响应摘要。
- 真实版本号、接口 URL、文档链接。
- 截图或日志摘要，不包含秘密。
- 失败原因和下一步。
