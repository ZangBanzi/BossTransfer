# BossTransfer 2.1.0 需求说明

## 产品目标

管理员只管理自己的 115 影视资源和客户使用授权。客户在自己的 NAS 上部署独立客户端，绑定自己的 115，并自行决定如何把已秒传的文件下载到本地。

## 管理端

- 使用独立本地账号登录；新数据卷默认 `admin/password`，可在 Web 页面修改。
- 使用 115 Open AppID 扫码绑定管理员资源账号。
- 在 Web 页面浏览并选择允许客户搜索的 115 目录。
- 创建客户，设置授权有效期和可激活设备数。
- 生成只显示一次的激活码，支持重新签发、撤销授权和释放设备。
- 只向有效设备返回搜索结果、秒传摘要和 115 二次校验区间摘要。
- 不接收、不保存客户的 115、CloudDrive2 或 qBittorrent 凭据。
- 不替客户选择或限制下载器。

## 客户端

- 可独立部署，不要求与管理端同机。
- 新数据卷默认 Web 账号 `admin/password`；环境变量只负责首次初始化。
- 使用管理端地址和一次性激活码在线激活。
- 下载前必须扫码绑定客户自己的 115，并可视化选择秒传目录。
- 搜索结果以影片目录归组，只展示可下载的视频、ISO、种子或磁力资源。
- 先把管理员资源秒传到客户 115，再从客户账号获取下载链接。
- 可视化选择 NAS 本地保存目录。
- CloudDrive2 和 qBittorrent 由客户自行配置，验证成功后才可选择。
- 授权失效、撤销或设备租约失效时不能搜索和发起新下载。

## 下载方式

- `system`：客户端使用客户 115 下载地址流式写入客户选择的本地目录。
- `clouddrive2`：客户使用账号密码或 API Token 接入 CD2，并选择与客户 115 秒传目录对应的云端目录；客户端读取真实文件下载链接，不创建搜索虚拟目录。
- `qbittorrent`：客户使用私网 WebUI 账号密码或 qBittorrent 5.2+ API Key；仅处理磁力链接和 `.torrent`。115 中的种子由客户端带官方 User-Agent 读取，再上传给本机 qB。

## 发布

- 正式支持 Linux Docker `amd64` 和 `arm64`。
- 提供合并部署、仅管理端、仅客户端三套 Compose。
- 正式包必须从干净的 `v2.1.0` 标签构建，并附 SHA256 清单。
- 升级时删除旧 BossTransfer 容器和镜像，保留管理端与客户端命名卷，并使用 `--no-cache` 重建。
- 原生 fnOS FPK 不属于 2.1.0 发布物。
