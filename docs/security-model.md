# BossTransfer 2.1.0 安全模型

## 信任边界

- 管理端信任管理员登录会话和已激活的客户设备凭据。
- 客户端信任自己的本地 Web 会话、中央管理端和客户主动配置的本地服务。
- 浏览器提交的资源编号、文件名、路径和下载器名称都不能直接作为可信数据使用。

## 账号与令牌

| 数据 | 保存位置 | 保护方式 |
|---|---|---|
| 管理端 Web 密码 | 管理端数据卷 | 加盐密码摘要 |
| 管理员 115 access/refresh token | 管理端数据卷 | AES-GCM |
| 授权码 | 管理端数据卷 | 只保存摘要，完整码只返回一次 |
| 客户端 Web 密码 | 客户端数据卷 | 加盐密码摘要 |
| 客户设备私钥与令牌 | 客户端数据卷 | AES-GCM |
| 客户 115 access/refresh token | 客户端数据卷 | AES-GCM |
| CD2 密码或 Token | 客户端数据卷 | AES-GCM |
| qB 密码或 API Key | 客户端数据卷 | AES-GCM |

密钥文件与加密数据保存在同一受限数据卷中，用于避免配置文件直接泄露明文。数据卷本身仍需由 NAS 权限和备份策略保护。

## 资源凭据

管理端搜索响应中的 `resource_id` 是 AES-GCM 加密的短期凭据，包含：

- 客户设备 ID；
- 管理员 115 文件 ID 与父目录；
- 文件名、大小、SHA1、提取码；
- 过期时间。

资源凭据绑定发起搜索的设备，默认十分钟过期。篡改、跨设备使用和过期都会被拒绝。浏览器无法读取其中的管理员 115 提取码。

## 秒传保护

- 客户端未绑定自己的 115 时，所有下载请求都被拒绝。
- 管理端只返回秒传所需的 SHA1、文件大小和前 128 KiB SHA1。
- 115 要求二次摘要时，管理端只读取指定范围并返回其 SHA1。
- 秒传状态不是成功时立即停止，不向客户返回管理员直链。
- 成功后只用客户 115 返回的提取码取得下载地址。

## 路径保护

- 系统下载目标必须位于 Docker 映射的固定根目录内。
- 页面目录选择器只返回固定根目录内的相对路径。
- 拒绝绝对路径、`..` 穿越和符号链接穿越。
- 文件先写入临时文件，完成后原子发布。

## 本地集成

- CD2 和 qB 地址只允许 `http` 或 `https` 所需格式，凭据不会返回浏览器。
- CD2 下载路径由客户已保存的云目录与可信资源文件名组合。
- qB 只接受磁力或由可信资源名确认的 `.torrent` 下载地址。
- 外部下载器只有在客户完成本地连接验证后才显示为可用。

## Web 安全

- 管理端和客户端使用独立的 HttpOnly 会话 Cookie。
- 修改操作要求 JSON 请求和同源检查。
- 首次默认账号必须修改密码后才能执行核心操作。
- HTTP 服务设置请求头、请求体、超时和响应大小限制。

生产部署应给中央管理端配置 HTTPS，并限制管理端控制台的公网访问范围。
